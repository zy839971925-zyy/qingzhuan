## 2. 已知技术方向（待通过原始源码复核）

Android Java 原生宿主 + WebView 承载 HTML/CSS/原生 JavaScript（现阶段不要无谓引入 React、React Native）。文件选择、真实格式识别、输入缓存、转换引擎、进度、结果管理、系统分享在原生侧实现。前端使用 GSAP（本地打包）管理分镜与文字错峰，Pointer Events + 单一 `p ∈ [0,1]` 管理跟手可逆交互；WebGL/GLSL 或等效高性能渲染实现局部透镜折射与色散，同时保留低成本渲染降级。GSAP、Shader、贴图等资源全部离线打包。

现有预览中有 `window.Native`，可见方法/事件示例：`pick()`、`removeInput(id)`、`clearInputs()`、`save(id)`、`saveAll(ids)`、`share(id)`、`open(id)`、`cancel()`、`haptic()`；`window.onNative(type, data)` 接收 `state`、`progress`、`complete`、`error`、`toast`。这是**预览所见**，并非可保证的最终原生接口；请与 Android Java 实现逐一比对、补充完整协议并做契约测试。

## 3. 产品交互（用户已确认，不要再次追问）

1. 首页视觉中心是占比大的圆角**虚线文件上传框**，中央加号，浅色提示“选择或拖入需要转换的文件”。初始没有底部液态玻璃罩。
2. 用户选择文件，系统验证真实类型与大小/访问权限，上传框平滑收缩为小文件卡片并向上运动。识别后，按真正已安装转换引擎的能力列出目标格式。不能提供实际上不支持的转换选项。
3. 目标格式选项逐个错峰弹出（建议间隔 60–100ms），文本以 GSAP 逐字/分词从模糊到清晰并自下向上轻微翻转；中文 Grapheme 分段与减少动态效果选项都要支持。
4. **只有在用户选中目标转换格式后**，底部大型**半圆液态玻璃罩**才从屏幕底边升起，附近显示操作提示“按住玻璃罩并向上滑动以转换”。不是胶囊！
5. 手指按住玻璃罩向上拖，半圆罩**连续缩小**为居中玻璃球，上方文件/格式 UI 同步上移、模糊并消失。反向拖动要即时还原，任意中间位置都可打断。失去捕获/提前松开可弹簧复位，提交前不能对真实文件产生副作用。
6. **只有玻璃球已到达中央有效区域且松手**才执行转换（例如 `p ≥ 0.92`，阈值应实测调节；不要沿用 Wabi 原复刻中以速度冲量提前判定的规则）。`p` 是视觉手势进度，不等于转换任务进度。
7. 转换中玻璃球停留在中央，内部是实际转换进度指示器（如果原生引擎没有可量化进度，则明确不确定进度，不能伪造百分比），UI 稳定显示正在处理，支持失败和取消状态。
8. 成功后玻璃球沿原路下降并放大回到底部半圆玻璃罩。中间文件从上方下落，渐渐去模糊、恢复清晰，展示真实生成文件和“转换完成”绿色勾号。结果可以保存、预览、分享；支持再次转换。
9. 转换失败、用户取消、应用切后台、旋转、WebView 重建时，界面和原生任务状态不能分叉。

## 4. 动效仓库的参考数学（不是要求照搬外观）

原参考文档使用 402×874 点坐标，`sx=width/402`、`sy=height/874`。大半圆中心在屏幕底部 `CY0 = height`、半径 `R0 = 245 sx`，中心小球半径 `R1=44 sx`、中心纵坐标 `CY1=0.469 height`。

- `p ∈ [0,1]`
- `R(p)=R0+(R1-R0)*p`
- `Y(p)=CY0+(CY1-CY0)*p`
- `Δp = -Δy / (CY0-CY1)`
- 原参考两端越界阻尼约 25%，侧向偏移 `150sx*tanh(Δx/(150sx))`；可作为实现灵感。
- 原参考弹簧 `{damping:15, stiffness:120, mass:1.05}`，具体参数需根据 WebView 设备触摸测试调整。
- 原参考文本模糊区间：wordmark `p=.05~.60`、提示 `p=.06~.30`；可通过独立 MotionConfig 调整，不要散落成硬编码。
- 保留原创光学素材、主题配色、文件图标；不得照搬 Wabi 商标/原设计专属文案。

## 5. 自动深浅色完整要求

- 默认跟随 Android 系统日夜模式；WebView 页面通过 Android 宿主同步主题状态，并使用 `prefers-color-scheme`/自定义 CSS Design Tokens 同步表面、文字、线条、渐变、阴影和 Shader uniforms。
- 页面主题、Android 状态栏、导航栏、启动背景保持一致；适配 Edge-to-Edge 和系统手势安全区域。
- 深色玻璃材质必须独立调高边缘识别与适当高光强度，不能机械反转浅色，避免色偏与暗部糊成一片。
- 如果设置项成本合理，可支持“跟随系统 / 浅色 / 深色”覆盖选项；优先保证默认自动模式稳定且无闪屏。
- `prefers-reduced-motion`/系统移除动画偏好：保留功能与直接操作，但去掉眩晕性的逐字翻转、长时模糊或惯性效果。

## 6. 高性能与可靠性

- 视觉目标优先稳定 60fps，硬件条件允许争取 90/120fps，但不能凭模拟器推断真实手机一定达成；要以帧时间证据确认。
- 缓存静态元素、按需绘制、避免每帧触发大片 DOM reflow/filter；由一个时间基准更新 `p`、光学参数与必要 DOM transform。注意 WebGL 不可以不经处理就直接采样任意 DOM 合成画面；先验证玻璃经过文字时的实时折射原型，再选背景合成方案。
- 设备级降级：高（局部实时折射与色散）、中（降低采样尺寸/色散通道）、兼容（较轻的伪折射材质），**保留跟手和可逆状态逻辑**。
- 提交前拖动可逆；提交之后的任务取消需要有原生 ACK 与任务状态一致性，不应仅凭反向动画当作取消成功。用唯一 task ID 过滤过期/乱序回调，重复提交去重。
- 原生长耗时任务不可占用 UI 线程；后台/暂停恢复后不丢失进度、输入引用与结果 ID。

## 7. 需从旧审查复核的高优先级缺陷

以下是先前对话的审查结论，**目前未拿到原始 Java 源码再次复核**：

- 发布 keystore 随源代码出现、构建脚本含凭据；先确认再处置，不能把它们复制进输出包/日志。
- `MainActivity` 在创建或屏幕重建时清理输入缓存/任务状态，可能导致旋转或进程恢复后文件丢失。
- Zip4j 大文件压缩或转换部分环节取消延迟，缺少细粒度取消状态处理。
- Target SDK 版本偏旧；核实 2026 年当前 Android/Google Play 提交要求、AGP 与依赖兼容性并更新到适当 targetSdk，不要凭本文件猜测所有依赖版本。
- 加密 PDF 异常路径可能残留临时文件，输入缓存和历史结果缺少完整容量/清理策略。
- 旧 UI 小字号及低对比度；新 UI 保证可访问性、按钮触控面积、文字对比度。

## 9. 最小验收用例

- PNG/JPEG/PDF 与未知扩展名文件进入后不靠扩展名谎报可转换格式。
- 目标格式未选中时，底部玻璃罩不出现；选中之后才升起。
- 在 `p=0.1/0.3/0.5/0.7/0.9` 拖动再向下返回，视觉/触发状态一致；未到阈值松开不转换。
- 到达阈值松手，只触发一次任务；连续点击和乱序回调不会重复转换。
- 完成/失败/取消后临时文件按策略清理，最终生成文件和 UI 一致。
- 深浅色切换时背景/文字/玻璃/系统栏同步，切换过程不白闪。
- 键盘、无障碍、减少动画和系统后退手势下能够完成核心操作。
- 帧率用 Android 真机记录；记录设备型号、Android 版本、WebView 版本、60/120Hz 和性能档位，给出实际测得结果，不编造测试数据。
